# 清理目标契约

在第一次盘点前，将下列模板完整写入项目专用归档目录的 `goal-contract.md`。这是每轮审查和最终验收的唯一目标来源，不要把聊天记录或目录名当作目标。

```markdown
# 运行时安全整理目标

## 目标

明确写出本次整理要实现的结果。

## 非目标

例如：不重写业务功能；不删除资料；不改变对外端口；不把私人数据写入 Git。

## 完整功能定义

列出必须仍然可用的启动入口、核心页面/API/训练或推理命令、数据恢复路径，以及需要保留的维护能力。

## 成功标准

- [ ] 目录和文件已完成全量盘点，并有功能分类。
- [ ] 每个移走项均有依赖检索证据、风险等级和归档理由。
- [ ] 归档副本的相对路径、字节数和 SHA-256 与源一致。
- [ ] 移动后通过列出的健康与功能探针。
- [ ] 至少一轮稳定审查没有新的安全移动项。
- [ ] 归档清单、审查记录和最终验收结果可复查。

## 范围与边界

写明允许修改的项目根、归档根及明确排除的外部路径。

## 风险与人工复核边界

列出链接/联接点、密钥、私有数据、运行中写入、未知依赖等必须人工复核的情形。

## 回滚

归档副本的恢复命令或步骤。恢复必须先核验归档清单。

## 验收证据

列出基线、每轮 Vn、移动清单、最终探针输出的位置。
```
